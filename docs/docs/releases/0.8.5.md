# RaBitQ Library 0.8.5 (unreleased)

These notes collect what is on `main` for the next 0.8 release. It adds the names that
0.9 will use and deprecates the 0.8 spellings they replace. Every 0.8 call keeps
working, with the same results; index files are unchanged.

## Python: names that change in 0.9

0.9 gives the three index classes one name for each concept (#232). This release
accepts both spellings and raises a `DeprecationWarning` for the old one, at your call
site. The [migration guide](../python_migration.md#from-08-to-09) lists each change.

- `HnswIndex.capacity` replaces `max_elements`, and `HnswIndex.reserve(num_points)`
  replaces `resize`. `reserve` only grows the capacity.
- `max_elements` is deprecated on `IvfIndex` and `SymqgIndex`; use `num_stored_points`.
- `IvfIndex.reserve_cluster(cluster_id, num_points)` replaces `reserve`.
- `IvfIndex(routing=...)` and `index.routing` replace `initializer`.
- `HnswIndex.search` and `SymqgIndex.search` take `ef_search=` instead of `ef=`. Passing
  the breadth by position is unaffected.
- The `search` options after the breadth (`high_accuracy`, `num_threads`) are
  keyword-only; passing them by position is deprecated.
- `nprobe=0` and `ef_search=0` for the default are deprecated; pass `None` or omit the
  argument. `num_threads=0` keeps meaning every available CPU.
- `HnswIndex` seeds above `2**32 - 1` are deprecated.

## Python: other changes

- `IvfIndex.set_centroids` takes `num_threads` (#231). Its default follows
  `OMP_NUM_THREADS`; before, building HNSW centroid routing always used every CPU.

## Coming in 0.9 without a warning

- `HnswIndex()` without `seed=` will draw a seed, as `IvfIndex` and `SymqgIndex` do,
  instead of using 100. Pass `seed=`, and `num_threads=1` to `add`, for a reproducible
  build.
- `repr(index)` will print `capacity=` and `routing=` where it prints `max_elements=`
  and `initializer=`.
